# Workspace Rules for AI Coding Assistant

## ⚠️ Не ломать то, что работает (Do Not Break Existing Code)

1. **Строгая обратная совместимость**:
   * Любые доработки или исправления ошибок (например, типизации или сборки) не должны ломать существующую логику работы приложения, механизмы авторизации или интеграции с внешними API (Firebase, GitHub).
   * Перед изменением вспомогательных утилит (например, заголовков авторизации или сетевых клиентов) необходимо проверить все места их использования в проекте.

2. **Обязательная локальная верификация**:
   * После внесения любых изменений в код агент обязан запустить и успешно выполнить:
     1. Проверку типов TypeScript: `npx tsc --noEmit`
     2. Сборку продакшн-бандла: `npm run build`
     3. Запуск юнит-тестов: `npm run test:run`
   * Сдача работы допускается только при 100% успешном завершении всех проверок.

3. **Бережное отношение к комментариям и типам**:
   * Не удалять и не менять существующие комментарии, если они описывают важные нюансы работы кода или обходные решения (workarounds) для мобильных устройств (iOS/Android).
